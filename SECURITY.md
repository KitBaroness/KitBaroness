# Security Policy

## Supported Versions

We support the following versions of our project with regular security updates. Older versions are not maintained.

| Version  | Supported               | End of Life Date |
| -------- | ----------------------- | ---------------- |
| 6.x.x    | :white_check_mark:       | Ongoing          |
| 5.x.x    | :white_check_mark:       | December 2024    |
| 4.x.x    | :x:                     | March 2023       |
| < 4.0    | :x:                     | Unsupported      |

For detailed information on our versioning strategy, visit [Version Policy](#null).

## Reporting a Vulnerability

We take security seriously. If you discover a vulnerability in our project, please follow the steps below:

1. **Contact Us**: Email us at `security@devcorp.org`. Please include:
   - The affected version.
   - A detailed description of the vulnerability.
   - Steps to reproduce the vulnerability (if possible).
   
2. **Response Time**: We will respond to your report within **72 hours**. We will also let you know the expected resolution timeline.

3. **Handling of Vulnerabilities**: We will work privately with you to resolve the vulnerability before making it public. Public disclosure of the vulnerability will only happen once a fix is in place.

### Bug Bounty

NO offer or rewards for responsibly disclosed vulnerabilities.

## Security Guidelines

We recommend the following steps to maintain security while using our project:

- Keep your dependencies updated to the latest stable versions.
- Use strong access controls for environments where our project is deployed.
- Regularly audit your environments for potential vulnerabilities.

For more details, refer to our [Security Best Practices](#null).

## Vulnerability Disclosure

Once we have resolved a reported vulnerability, we will publicly disclose:
- The nature of the vulnerability.
- Acknowledgment of the reporter (if permission is granted).
- Steps taken to fix the issue.

For more details, check out our [Vulnerability Disclosure Policy](#null).
